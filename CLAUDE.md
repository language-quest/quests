# language_quest

Изучаемый язык проекта — **испанский**. Все новые квесты, учебные реплики,
варианты ответа и языковые ловушки разрабатываются на испанском, не на английском.

Два квеста с разной аудиторией и **несвязанными** движками (общий только голос):
`web/index.html` + `web/js/app.js` — Каперусина (ребёнок с родителем);
`web/rocodromo.html` + `web/js/rocodromo.js` — «La ruta secreta» (взрослый один).
Общее: `web/js/speech.js`, `matchIntent`/`normalize` из `web/js/engine.js`,
прокси `tools/slng-proxy.mjs`. Объединять движки не надо — это взвешено и отклонено.

## Главное правило: картинка не переводит слово

Игра учит языку перебором и ошибками. Игрок должен сам понять, какое испанское
слово к какому предмету или действию относится, — и узнать это из **реакции на свой
выбор**, а не из картинки рядом с текстом.

Отсюда запрет: **на одной карточке не может быть одновременно испанской фразы
и картинки, которая её переводит.** «Quiero subir» рядом с ⬆️ — это готовый ответ,
выбирать нечего.

Допустимы ровно две формы карточки:

| Форма | Что на карточке | Что проверяет |
|---|---|---|
| **картинка** | предмет/цвет/форма + нейтральная подпись `A` / `B` / `C` (или без подписи) | услышал ли игрок слово в реплике персонажа |
| **фраза** | испанский текст, картинки нет | понимает ли игрок, что фраза значит |

Ошибка не наказывается, а объясняется: персонаж отвечает на неверный выбор так,
чтобы из ответа стало понятно значение. Перебор — это и есть механика обучения,
а не обход защиты.

Следствия, которые легко нарушить по инерции:
- не подписывать предметы (сцена снаряжения — картинки без названий);
- не делать персонажа узнаваемым там, где его надо найти по описанию
  (три фигуры у стен безлики, иначе «junto a la pared roja» решается глазами);
- не ставить над вопросом картинку, дублирующую карточки ответов;
- эмодзи — такая же подсказка, как фотография; «нейтральных» эмодзи почти не бывает.

## Внутри игры нет русского

Реплики, вопросы и реакции на ошибку — только по-испански. Перевод живёт
в свёрнутой панели `vocabulario` и больше нигде. Язык перевода — **английский**,
не русский: игрок необязательно русскоязычный. Русский остаётся только в общении
с автором и в файлах `pm/`.

## Прокси

Прокси не только прячет ключ: перед синтезом он прогоняет текст через `ttsText()`,
после синтеза — аудио через `trimWavSilence()` (оба в `tools/tts-prep.mjs`, там же
написано, из каких поломок они выросли). Ключ кэша считается от нормализованного
текста, поэтому прогрев и рантайм не расходятся.

`node tools/slng-proxy.mjs` на порту 5179 пользователь держит запущенным сам.
Перед запуском своего сервера: `curl -s localhost:5179/api/health`. Отвечает —
просто открывать `http://localhost:5179/web/rocodromo.html`.

## Задачи приходят через доску

Задачу ставит PM (Codex) файлом в `pm/tasks/`, а не в чате; разработчик и QA —
отдельные сессии, запускаемые `tools/pm-run.mjs`. Контракт ролей, статусы и формат
отчётов — в `pm/README.md`. Команды `/tz <ID>` и `/qa <ID>` включают роль.

Отчёты пишутся в `pm/` **главного** чекаута (`$PM_ROOT`), а не в копию внутри
worktree, иначе PM не увидит их до merge.

## Проверка перед сдачей

```bash
node tools/validate-tts-text.mjs       # орфография озвучиваемых строк, сети не нужно
node tools/test-rocodromo-intent.mjs   # интент-гейт, сети не нужно
node tools/test-rocodromo-voice.mjs    # круг синтез → SLNG STT → гейт
node tools/warm-rocodromo.mjs          # прогреть кэш синтеза после правки реплик
node tools/trim-tts-cache.mjs          # срезать тишину в свежих клипах (идемпотентно)
```
