# Language Quests — техническая архитектура и требования к интерфейсу

**Платформы:** iOS, Android, Web
**Продукт:** кооперативные разговорные квесты для изучения испанского, родитель + ребёнок 3–4 лет
**Документ описывает:** стек, конвейер диалога, контент-пайплайн, приватность, требования к UI

---

## 0. Главное в одном абзаце

Архитектура почти целиком выведена из геймдизайна, а не выбрана отдельно. Три решения из дизайн-документов диктуют всё остальное: **признак не передаётся модели в контексте состояния 1** (значит, сборка промпта — на сервере, и она пер-состоянийная), **застрять нельзя** (значит, у каждого сгенерированного момента есть авторский фолбэк, и игра проходима офлайн), и **большая часть реплик — авторские, а не генерируемые** (значит, критичный путь не зависит от задержки LLM вообще).

Последнее — самый важный архитектурный рычаг. Выдача улики, подсказки и финал озвучены заранее и играются локально за ~0 мс. Модель отвечает только за свободную болтовню вокруг них.

## 1. Ограничения, которые задаёт геймдизайн

| Требование дизайна | Что оно означает технически |
|---|---|
| Признака нет в контексте в состоянии 1 | Промпт собирается на сервере по состоянию сцены; клиент не хранит текст улики до перехода |
| Улику открывает просьба **или** поддержанный маршрут | Переход — событие игрового рантайма, а не решение модели. Модель не может выдать улику, даже если захочет: её нет в контексте |
| Застрять нельзя | Каждый генерируемый момент имеет авторский фолбэк; таймеры лестницы подсказок работают локально и не зависят от сети |
| Реакция мира на голос ребёнка | Распознавание закрытого словаря из 3–6 слов, щадящий порог, деградация в «вместе» и в касание |
| Касания во время речи не обрывают реплику | Очередь ввода с политикой на событие: немедленно / отложить / игнорировать |
| Матрица 110 / 101 / 011 | Валидатор в CI, а не соглашение между авторами |
| Ребёнок не читает | Вся детская информация — иконка + звук + анимация; текста в детской зоне нет |
| 9–12 минут с трёхлеткой | Мгновенное возобновление после прерывания, включая позиции таймеров |

## 2. Стек

### Решение

| Слой | Выбор | Почему |
|---|---|---|
| Клиент (iOS / Android / Web) | **Expo (React Native + react-native-web), TypeScript** | Один JS-рантайм на трёх платформах. Игровой рантайм с правилами выдачи улик существует в единственном экземпляре — расхождение реализаций здесь было бы худшим классом багов |
| Персонажи и анимация | **Rive** | Стейт-машины Rive ложатся на состояния сцены один в один: «шёпот → громко», уровень доверия волка — это входы стейт-машины, а не отдельные ролики. Рантаймы под все три платформы, файлы на порядок легче видео |
| Фоны, предметы | Статичные растры + SVG для иконок улик | Никакой генеративной графики в рантайме |
| Игровой рантайм | Чистый TS-пакет `@lq/runtime`, без I/O | Детерминированный, тестируемый, переиспользуемый на сервере для валидации |
| Бэкенд | **Node 22 + Fastify**, TypeScript | Общие типы с клиентом и контентом |
| Транспорт диалога | **WebSocket** | Дуплекс: аудио вверх, события и аудио вниз. Проще, чем SSE + отдельная загрузка |
| Голосовой слой (STT/TTS/роутинг) | **SLNG** | См. раздел 11. Закрывает Listen и Speak целиком; интент-гейт остаётся наш |
| Модель | **`claude-opus-5`** | См. раздел 4.4 — там же честный расчёт и альтернатива |
| Хранилище | Postgres (аккаунты, прогресс) + S3/R2 + CDN (квест-паки) | — |

### Почему не Unity / не нативно

Игра — это иллюстрированная книжка с тапами, звуком и голосовым слоем, а не физика и не 3D. Unity даёт избыточный вес веб-сборки и плохую доступность текста. Раздельные нативные клиенты дали бы три реализации правил гейтинга улик — ровно то, что три раунда ревью учили не допускать.

### Где всё-таки нужен натив

Expo не закрывает три вещи, под них пишутся нативные модули:

- **Аудиосессия.** iOS `AVAudioSession` (категория, дакинг, прерывания, смена маршрута при подключении наушников), Android `AudioManager` + audio focus. Звонок посреди сцены не должен ломать состояние.
- **Распознавание речи ребёнка на устройстве** (раздел 5).
- **Родительский гейт** для покупок — нативный, чтобы соответствовать требованиям детских категорий сторов.

## 3. Слои и границы

```
┌─ Контент: квест-паки ────────────────────────────────────┐
│ quest.json (схема Zod) + арт + Rive + предрендеренный TTS │
│ версионированные, иммутабельные, раздаются через CDN      │
└───────────────────────────────────────────────────────────┘
                          ↓ скачивается и кэшируется целиком
┌─ @lq/runtime — чистый TypeScript, без I/O ───────────────┐
│ • граф сцен и состояния свидетелей (1 / 2)                │
│ • реестр полученных улик (заработанное не отбирается)     │
│ • лестница подсказок: 0 / 1-я ошибка / 45 / 75 / 120 сек  │
│ • вычисление матрицы и проверка инварианта                │
│ • политика ввода: немедленно / отложить / игнорировать    │
│ • снапшот сессии для возобновления                        │
└───────────────────────────────────────────────────────────┘
        ↓ один и тот же пакет                    ↓ он же на сервере
┌─ Оболочки: Expo ──────────────────┐   ┌─ Бэкенд ──────────────────┐
│ iOS · Android · Web               │   │ • сборка промпта по состоянию│
│ рендер, звук, ввод, Rive          │◄─►│ • ASR родителя (стриминг)   │
│ локальные таймеры подсказок       │ WS│ • интент-гейт (без LLM)     │
│ предрендеренное аудио локально    │   │ • Claude для свободных реплик│
└───────────────────────────────────┘   │ • TTS живых реплик          │
                                        │ • телеметрия                │
                                        └─────────────────────────────┘
```

**Граница проведена так:** клиент владеет всем, что должно работать мгновенно и офлайн. Сервер владеет тем, что требует ключей и сборки контекста. Ни одно касание не ходит на сервер.

## 4. Конвейер диалога — самая сложная часть

### 4.1 Ключевая развилка

Реплика родителя идёт по одному из двух путей, и **игрово критичный путь не использует LLM вообще**.

```
родитель нажал «говорить» → стриминг аудио → ASR (испанский)
                                                  ↓
                                        ИНТЕНТ-ГЕЙТ (локальный матчер)
                                     ┌────────────┴────────────┐
                        совпало с одной         не совпало
                        из трёх функций               ↓
                              ↓                  Claude: свободная
                     переход состояния            реплика в роли
                              ↓                        ↓
                   ПРЕДРЕНДЕРЕННОЕ аудио          стриминг TTS
                   улики — играется локально            ↓
                              ↓                   валидатор реплики
                        ~300–500 мс                ~700–1500 мс
```

**Интент-гейт** — это не вызов модели, а матчер по списку допустимых формулировок из дизайн-документа (`más alto`, `no te oigo`, `habla alto`, `más fuerte`…) с нормализацией и нечётким сравнением. Работает за миллисекунды, детерминирован, тестируется юнит-тестами и не стоит денег. LLM подключается фолбэком только при неуверенном совпадении.

Следствие: **момент, ради которого существует игра — выдача улики — не зависит ни от сети, ни от задержки модели, ни от квоты.**

### 4.2 Бюджет задержки

| Путь | Цель | Из чего складывается |
|---|---|---|
| Интент-гейт → улика | **≤ 500 мс** | ASR-финализация 200–400 мс + матчер <10 мс + локальное аудио 0 мс |
| Свободная реплика | **≤ 1200 мс** до первого звука | ASR 300 мс + TTFT модели + TTFB TTS |
| Порог провала | **2000 мс** | Дольше — персонаж кажется мёртвым |

**Задержка маскируется характерами персонажей.** Это не метафора, а рабочее решение: пока идёт генерация, Отто клюёт носом, Рита дёргает хвостом, Лоло озирается. Три придуманных для геймдизайна причуды оказались готовыми состояниями ожидания — их и нужно использовать как индикатор загрузки, никаких спиннеров.

### 4.3 Запрос к модели

Свободная реплика — короткая, в роли, с жёсткими ограничениями. Системный промпт персонажа стабилен и кэшируется; переменная часть идёт после него.

```typescript
import Anthropic from "@anthropic-ai/sdk";

const client = new Anthropic();

const stream = client.beta.messages.stream({
  model: "claude-opus-5",
  max_tokens: 300,
  speed: "fast",                        // research preview, только Opus 5 / 4.8
  betas: ["fast-mode-2026-02-01"],
  output_config: { effort: "low" },     // короткая реплика — думать почти не нужно
  system: [
    {
      type: "text",
      text: characterPrompt(characterId, sceneState),  // БЕЗ признака в состоянии 1
      cache_control: { type: "ephemeral", ttl: "1h" },
    },
  ],
  messages: [
    ...sceneHistory,
    { role: "user", content: parentTranscript },
  ],
});

stream.on("text", (delta) => ttsSink.write(delta));   // TTS начинает говорить, не дожидаясь конца
const final = await stream.finalMessage();
```

Что здесь важно:

**`effort: "low"`, но мышление не выключено.** На Opus 5 адаптивное мышление включено по умолчанию, и отключать его не стоит: при `thinking: {type: "disabled"}` модель иногда пишет вызов инструмента прямо в видимый текст и может уронить в ответ служебные теги. Понижение effort снимает задержку и стоимость без этих побочек.

**Fast mode** даёт до 2.5× скорости выдачи токенов на Opus 5 — прямо в цель для голосового диалога. Платится премией ($10/$50 за MTok вместо $5/$25), живёт на отдельном лимите и доступен только на первопартийном Claude API (не на Bedrock / Vertex / Foundry). Переключение `speed` инвалидирует кэш — не менять его в середине сессии.

**Префилла ассистента нет** — на Opus 5 он возвращает 400. Формат ответа задаётся системным промптом, а валидируется уже на сервере (см. ниже).

**Отказ модели.** Стоит включить серверный фолбэк: `betas: ["server-side-fallback-2026-07-01"]` + `fallbacks: "default"`. Сочетание с fast mode нужно проверить на интеграции — в документации эта комбинация явно не описана. Впрочем, для игры это вторая линия: первая — авторский фолбэк, который срабатывает на любой сбой.

### 4.4 Кэширование промптов персонажей

Системный промпт персонажа — правила роли, темп речи, контракт длины, закрытый список глаголов — одинаков для всех игроков и всех сессий. Его нужно кэшировать.

- Кэш — **префиксное совпадение**: порядок рендера `tools` → `system` → `messages`. Стабильное держим в `system`, переменное (транскрипт, история сцены) — строго после.
- **Никаких `Date.now()`, `uuid` и несортированного JSON в системном промпте.** Это классический тихий инвалидатор.
- `ttl: "1h"` вместо дефолтных 5 минут — у нас сессии по 10 минут и пики по вечерам.
- **Минимальный кэшируемый префикс — 512–4096 токенов в зависимости от модели.** Промпт персонажа может оказаться короче порога и не закэшироваться молча. Проверять по `usage.cache_read_input_tokens`: если ноль на повторных запросах — либо инвалидатор, либо промпт не дотянул до порога. Во втором случае имеет смысл вынести в системный промпт общие для всех персонажей правила (контракт, уровень языка, правила рекаста), чтобы префикс стал длиннее и общее кэшировалось между персонажами.

**Смена состояния сцены не должна ломать кэш.** Opus 5 поддерживает системные сообщения в середине разговора: `{ role: "system", content: "..." }` добавляется в `messages[]`, а не правит верхнеуровневый `system`. Кэшированный префикс сохраняется. Ограничения: такое сообщение должно идти после `user`-сообщения, не может быть первым и должно быть либо последним, либо за ним идёт `assistant`. Это же канал для операторских инструкций, устойчивый к инъекции.

### 4.5 Валидатор реплики — обязателен

Ни одна сгенерированная реплика не идёт в TTS без проверки:

1. не длиннее двух предложений;
2. **не содержит токена улики**, если сцена в состоянии 1 (страховка второго уровня — в контексте его и так нет);
3. для свободных ответов — только настоящее время плюс закрытый список `vi / oí / estaba / rodó / se llevó`;
4. нет латиницы вне испанского, нет служебных тегов, нет обращений к «пользователю».

Провал → один ретрай → **авторская безопасная реплика**. Ребёнок никогда не слышит нарушающую строку.

### 4.6 Выбор модели: честный расчёт

Ориентир: ~15 свободных реплик за сессию, ~2000 входных токенов (в основном из кэша), ~60 выходных.

| Модель | За сессию (оценка) | Комментарий |
|---|---|---|
| Opus 5 | ~$0.08 | База |
| Opus 5 + fast mode | ~$0.15 | Вдвое дороже, заметно отзывчивее |
| Sonnet 5 | ~$0.03 | |
| Haiku 4.5 | ~$0.015 | Меньший контекст (200K, нам хватает), `effort` не поддерживает, мышление через `budget_tokens` |

Плюс ASR и живой TTS — ещё примерно столько же. Итого порядка **$0.15–0.30 за сессию** на Opus 5 с fast mode.

**Рекомендация: начинать на `claude-opus-5` с fast mode.** Реплики короткие, поэтому разница в абсолютных деньгах невелика, а качество удержания роли на A1–A2 с жёстким контрактом — именно то, на чём дешёвые модели сыплются: начинают выдавать улику, растягивать реплики и выходить из характера. Удешевление — осознанное решение после того, как станет видно, держит ли модель контракт; мерить это нужно на эвал-наборе из реальных реплик родителей, а не на глаз.

## 5. Речь ребёнка — отдельная задача, отдельное решение

Это **не** та же проблема, что распознавание родителя, и общий ASR здесь вреден.

**Словарь закрыт: 3–6 слов.** `pan`, `queso`, `manzana`, `rosa`, `azul`, `rojo`. Нужно не распознавание, а **детекция ключевых слов** с очень низким порогом.

**Обработка на устройстве, аудио не покидает телефон.** Это одновременно требование приватности (голос ребёнка — чувствительные данные), выигрыш по задержке и единственный способ работать офлайн.

| Платформа | Решение |
|---|---|
| iOS | `SFSpeechRecognizer` в режиме on-device для испанского, ограниченный контекстными подсказками |
| Android | `SpeechRecognizer` с офлайн-пакетом; доступность офлайн-испанского зависит от устройства, поэтому нужен запасной вариант |
| Web | **Web Speech API не подходит** — в Chrome он отправляет аудио на серверы Google, что для детского голоса неприемлемо |

**Отсюда решение: один бандлируемый WASM-детектор ключевых слов на все три платформы**, с нативными API как ускорением там, где они доступны офлайн. Паритет поведения важнее оптимальности на каждой платформе, а на вебе альтернативы всё равно нет.

**Деградация уже описана в геймдизайне и реализуется как есть:** 15 сек — «скажем вместе», 30 сек — касание или подтверждение взрослым. Голос даёт более яркую реакцию мира, но никогда не блокирует.

**Микрофон открыт ограниченное время.** Родитель говорит по нажатию (push-to-talk), ребёнку окно открывается на несколько секунд после приглашения. Постоянно открытого микрофона в детском приложении быть не должно — ни по приватности, ни по стоимости.

## 6. Контент-пайплайн: превратить выводы ревью в CI

Квест — это данные, а не код. Пак: `quest.json` + арт + Rive + предрендеренный TTS, версионированный и иммутабельный.

**Валидаторы блокируют мердж.** Каждый вырос из конкретной ошибки, найденной на ревью:

| Валидатор | Что проверяет | Откуда взялся |
|---|---|---|
| `matrix-profiles` | Три неверных места дают профили **110 / 101 / 011, каждый ровно раз**, считая **совпадение с уликой**, а не наличие свойства | Формулировка «совпадает по двум» пропускала набор 110/110/011 с лишней уликой |
| `clue-leak` | Текст состояния 1 не содержит лемму улики ни на одном языке | Улики звучали до просьбы |
| `variant-completeness` | У каждого варианта есть все заменяемые элементы: реплика выдачи, медленный повтор, действие закрепления, карточка улики, реакция на каждое неверное место | В варианте B закрепление волка оставалось звуком ручья, противореча его же улике |
| `sensory-affordance` | Каждый признак предъявляется хотя бы одним каналом: сэмпл, подсветка или анимация | Звук и запах нельзя проверить по картинке |
| `absence-shown` | Отсутствие признака изображается чем-то (шелест, сухая листва), а не пустотой | Пустой экран неотличим от несработавшей анимации |
| `character-capability` | Волк несёт только звуковой признак; водопад не может быть беззвучным | Перестановка признаков ломала смысл |
| `tts-coverage` | У каждой авторской реплики есть отрендеренный файл во всех локалях | Игра обязана быть проходимой офлайн |
| `tts-orthography` | Озвучиваемая строка — только испанская орфография и знаки препинания | `«ocho»` синтезировалось как [oʃo] («ошо»): Aura-2 не узнаёт слово, к которому приклеена ёлочка |
| `es-level` | Свободные шаблоны — настоящее время плюс закрытый список форм | Список глаголов расходился со сценарием |

Первые два — самые ценные. Они автоматизируют ровно то, на чём дизайн ломался дважды.

**TTS авторских реплик рендерится на этапе сборки пака**, не в рантайме: постоянные голоса персонажей, нулевая задержка, работа офлайн, отсутствие дрейфа между сессиями.

## 7. Офлайн и деградация

| Что отвалилось | Что происходит |
|---|---|
| Сеть полностью | Квест **проходится целиком**. Все авторские реплики, улики, подсказки и финал локальны. Пропадает только свободная болтовня: персонажи отвечают авторскими репликами из пула |
| Модель медленная / лимит | Таймаут 1.5 сек → авторский фолбэк. Игрок не замечает |
| ASR не сработал | Лестница подсказок идёт своим чередом; на 75 сек доступно «сказать вместе», на 120 — автопереход |
| Микрофон запрещён | Игра полностью проходима: речевой шаг заменяется поддержанным маршрутом с первой секунды. Экран объясняет, что можно включить микрофон в настройках |
| Приложение свернули | Снапшот сессии на каждую смену состояния, включая позиции таймеров. Возврат — ровно туда же |

**Проверяемое свойство:** квест обязан проходиться в авиарежиме с выключенным микрофоном. Это регрессионный тест, а не пожелание.

## 8. Данные, приватность, комплаенс

Аудитория — дети до 13 лет. Это самый жёсткий регуляторный режим, и он влияет на архитектуру, а не только на юридический текст.

**Аккаунт только у родителя.** У ребёнка нет профиля, логина и идентификатора между устройствами.

**Голос ребёнка не покидает устройство. Никогда.** Ни для распознавания, ни для «улучшения качества», ни в логи. Это и есть причина выбора on-device детектора из раздела 5.

**Аудио родителя — эфемерно.** Стримится в ASR, транскрипт живёт в памяти сессии, аудио не пишется на диск. Транскрипт нужен для разбора речи в родительском отчёте — это отдельная функция с отдельным согласием и кнопкой удаления.

**Телеметрия — только события, без содержания.** Ни транскриптов, ни аудио, ни детских высказываний.

**Что это запрещает:** сторонние аналитические SDK, собирающие идентификаторы; рекламу вообще; поведенческий таргетинг; социальные функции. Детские категории App Store и Google Play это и так требуют — совпадение полезное.

**Покупки — за родительским гейтом**, нативным, не веб-модалкой.

**Регионы.** Российская аудитория — 152-ФЗ; европейская — GDPR-K и верифицируемое согласие родителя; США — COPPA. Практический вывод для архитектуры: данные разделены по регионам хранения, а состав собираемых данных минимизирован до того, что нельзя не собирать. Конкретную реализацию согласия нужно проверить с юристом до релиза — это единственный пункт документа, который я не могу закрыть технически.

## 9. Телеметрия под метрики геймдизайна

События спроектированы под то, что дизайн-документ просит измерять, и ни под что больше.

```
clue_obtained     { quest, variant, character, route }
                    route: self | after_sample | together | auto
                    ← четыре категории раздельно: одна доля «поддержанных»
                      не различает сложность, предпочтение семьи и сломанный микрофон

hint_shown        { character, at_ms, trigger }
child_utterance   { target_word, detected: bool, route: voice|together|tap, silent: bool }
                    ← silent различает молчание и неудачное распознавание

place_selected    { place, correct, clues_held, attempt_n }
search_find       { item, taps_before_find, hint_played_at_ms }
                    ← отвечает на вопрос, окупается ли объяснение родителя

idle_gap          { scene, ms }        ← прокси «на какой минуте ребёнок отвлёкся»
scene_duration    { scene, ms, hit_cap: bool }
session_end       { completed, total_ms, interruptions }
```

Сигнал «перенос просьбы» считается не событием, а агрегатом: применил ли родитель речевую функцию к другому персонажу или в следующей сессии **без** предшествующего `hint_shown`.

## 10. Требования к интерфейсу

### 10.1 Два зрителя, один экран

Главное отличие от обычного детского приложения: на экран смотрят двое, и им нужно разное.

**Зонирование обязательно.**

- **Детская зона** — центр и нижние две трети. Крупные цели, высокий контраст, **текста нет вообще**. Минимальная цель касания — **60pt** (не 44: у трёхлетки моторика хуже, и он часто тыкает всей ладонью).
- **Родительская зона** — верхняя полоса и края. Испанский текст, кнопка образца, «сказать вместе», субтитры. Мелко, спокойно, не конкурирует за внимание.
- **Ничто из родительской зоны не должно быть ближе 60pt к детской цели** — иначе ребёнок нажмёт кнопку взрослого.

**Целевое устройство — планшет в ландшафте.** Двое у одного экрана — это iPad. Телефон поддерживается, но в портрете компоновка перестраивается вертикально: родительская полоса сверху, сцена снизу. Веб — ноутбук, те же зоны.

### 10.2 Политика ввода

Требование дизайна «касания во время речи не обрывают реплику» реализуется как маршрутизатор событий с политикой на каждый тип:

| Политика | Что попадает | Поведение |
|---|---|---|
| **Немедленно** | Безопасные реакции: волк моргнул, Рита дёрнула хвостом, фоновые поглаживания | Срабатывает сразу — экран обязан отвечать на палец всегда |
| **Отложить** | Переходы между сценами, выдача улики | Ставится в очередь и исполняется после конца реплики |
| **Игнорировать** | Повторный запуск уже идущей реплики, перезапуск испуга волка | Гасится молча |

**Два разных касания на карте.** Касание места — изучить (звук, подсветка, запах), ничего не решает. Переход — отдельная кнопка `¡Vamos allí!` на карточке изученного места. Случайным тычком уйти не туда нельзя.

### 10.3 Звук

Аудио — основной канал, и обращаться с ним нужно как с основным.

- **Разблокировка контекста жестом.** В вебе и особенно в iOS Safari аудио не запускается без пользовательского жеста. Ритуал входа — все машут и говорят `¡Hola, bosque!` — это естественное место для разблокировки: игрок и так касается экрана. Дизайн и платформа здесь совпали, отдельного экрана «нажмите, чтобы включить звук» не нужно.
- **Беззвучный режим.** Игра без звука бессмысленна. Не обходить переключатель молча: определить беззвучный режим и показать понятное объяснение — решение остаётся за родителем.
- **Прерывания.** Звонок, будильник, наушники, другое приложение — пауза, корректное восстановление сессии, повтор прерванной реплики с начала.
- **Дакинг** фоновой музыки под речью персонажа, а не микс поверх.

### 10.4 Состояния ожидания

**Спиннеров нет.** Ожидание всегда выглядит как поведение персонажа: Отто клюёт носом, Рита перебирает лапами, Лоло озирается. Если ожидание превысило 2 секунды — персонаж начинает свою «идлящую» реплику из авторского пула, а результат генерации либо приходит к этому моменту, либо отбрасывается в пользу авторского фолбэка.

### 10.5 Прерывания и возобновление

Ребёнок уйдёт посреди сцены — это норма, а не исключение.

- Снапшот на каждую смену состояния, включая позиции таймеров лестницы подсказок.
- Возврат в приложение — **ровно на то же место**, без экрана «продолжить?» и без повтора пройденного.
- Если прошло больше суток — короткое напоминание, что мы искали, голосом Каперусины.

### 10.6 Доступность

- **Субтитры испанской речи для родителя** — это не только доступность, но и функция понимания. Включены по умолчанию, выключаются.
- Регулировка темпа речи персонажей (отдельно от игровой механики темпа — глобальный множитель).
- `prefers-reduced-motion` — убирает амбиентную анимацию, оставляет функциональную.
- Высококонтрастная тема.
- Ни одна игровая информация не передаётся **только** цветом: у улик есть иконка и форма.

### 10.7 Языки

- **Язык интерфейса** (русский и далее) отделён от **языка игры** (испанский) на уровне контента. Это два независимых измерения: русскоязычная семья учит испанский, англоязычная будет учить тот же испанский.
- Испанские реплики, их субтитры и озвучка **не переводятся никогда** — это предмет изучения.
- Переводятся: UI, родительские подсказки, отчёт, подписи улик.

## 11. Внешние сервисы: SLNG

**Решение принято: используем.** Хакатон, SLNG — спонсор. Раздел описывает, как встроить их максимально глубоко там, где это правильно, и где проходит граница, которую не двигает никакое спонсорство.

### Что берём

SLNG модульный — «use SLNG speech models and the Context Router with your existing orchestrator», брать целиком не обязательно. Их три стадии ложатся на наш конвейер так:

| Стадия SLNG | Берём | Как |
|---|---|---|
| **Listen** (STT) | **Да, целиком** | Стриминговое распознавание испанского для родителя, плюс их фронтенд: шумоподавление, VAD, определение языка, разделение говорящих |
| **Think** (Context Router) | **Да, но за нашим гейтом** | Подключается как `custom_llm` OpenAI-совместимым эндпоинтом. Обрабатывает только свободные реплики |
| **Speak** (TTS) | **Да, для живых реплик** | Авторские реплики остаются предрендеренными и локальными |

**BYOK** — регистрируем свой ключ Anthropic, модель остаётся наша.
**Регион** выбирается на запрос через базовый URL (`eu-west.api.slng.ai` и другие, 14 регионов).
**Для скорости разработки:** `npx skills add slng-ai/skills` ставит скиллы для кодящего агента — на хакатоне это экономит часы.

### Listen — здесь главная польза

У нас худший акустический сценарий из возможных: шумная комната, рядом трёхлетка, родитель говорит по-испански с русским акцентом и неуверенной просодией. Качество фронтенда STT прямо определяет, сработает ли интент-гейт, то есть получит ли игрок улику.

**Разделение говорящих потенциально отменяет push-to-talk.** Я закладывал его в разделе 5 именно потому, что игра не может отличить родителя от ребёнка. Если SLNG отделяет говорящих надёжно, микрофон можно держать открытым в сцене, и разговор станет естественнее. Проверить на хакатоне; если не взлетит — push-to-talk остаётся как был.

### Think — интент-гейт остаётся перед роутером

Это не компромисс с их архитектурой, а совпадение с ней. Их Stage 02 описан как «decide whether a turn needs full LLM reasoning, local inference, or no inference at all». **Наш интент-гейт — это и есть ветка «no inference», просто реализованная у нас.**

Причина держать её у себя не в недоверии к роутеру, а в типе требования: к переходу состояния привязана **гарантия** (автопереход на 120-й секунде, «застрять нельзя»). Классификатор вероятностный, а гарантию нельзя строить на вероятностном компоненте. Плюс гейт — это матчер по списку формулировок, его писать полчаса.

Схема остаётся прежней, меняется только исполнитель правой ветки:

```
ASR (SLNG Listen) → НАШ интент-гейт
                  ├─ совпало → переход + локальное аудио улики   (~300–500 мс, без сети)
                  └─ не совпало → SLNG Context Router → Claude    (свободная реплика)
                                       ↓
                                 НАШ валидатор реплики
                                       ↓
                                 SLNG Speak (TTS)
```

**Валидатор реплики остаётся нашим и обязателен** (раздел 4.5): не длиннее двух предложений, нет токена улики, закрытый список глагольных форм. Провал → авторский фолбэк.

### Открытый вопрос, который не блокирует хакатон

Роутер подключается OpenAI-совместимым URL. Через такую абстракцию, скорее всего, **не проходят** специфичные для Anthropic параметры: `cache_control`, `speed: "fast"`, `output_config.effort`, системные сообщения в середине разговора. Это надо проверить в первый же день.

**Почему это не блокер на хакатоне:** кэш промптов и fast mode — оптимизации стоимости и задержки при масштабе. На демо сессий десятки, стоимость нерелевантна, а критичный путь и так не ходит в модель. **Почему это важно после:** при тысячах сессий потеря кэша и fast mode — это и деньги, и те самые 2.5× отзывчивости.

Запасной вариант, если параметры не проходят: свободные реплики идут напрямую в Anthropic мимо роутера, Listen и Speak остаются на SLNG. Интеграция при этом сохраняется на двух стадиях из трёх.

### Граница, которую спонсорство не двигает

**Голос ребёнка не уходит в SLNG. Ни в каком режиме.** Это не оценка их продукта — это свойство детского аудио как категории данных. On-device детектор ключевых слов из раздела 5 остаётся.

**Квест обязан проходиться офлайн.** Авторское аудио остаётся локальным и предрендеренным — это одновременно и офлайн, и ноль задержки на выдаче улики. Runtime-кэш синтеза у SLNG решает ту же задачу слабее, потому что требует сети.

Обе границы означают, что SLNG у нас — **ускоритель некритичного пути**, а не фундамент. Если на демо отвалится сеть, квест доиграется.

### Что спросить у них на площадке

1. Проходят ли через Context Router поля `cache_control`, `speed`, `output_config` при BYOK Anthropic.
2. Можно ли вклиниться между стадиями — наш валидатор между Think и Speak.
3. Можно ли проиграть в ту же сессию своё предрендеренное аудио.
4. Насколько надёжно разделение говорящих на двух людях у одного микрофона, один из которых ребёнок.
5. Режим без удержания аудио; позиция по голосу несовершеннолетних (в списке сертификаций ISO 27001, SOC 2, HIPAA, GDPR — COPPA нет).
6. Методика замера «200–300 мс меньше на реплику» — относительно какой базы.

### UNMUTE

У них есть открытый стандарт описания голосового агента как кода — промпты, инструменты, модели, язык, регионы в одном файле, переносимо между SLNG, Pipecat и LiveKit. Нам всё равно нужен формат конфига персонажа, и изобретать его с нуля незачем: берём UNMUTE как основу, добавляя своё поле состояния сцены.

## 12. Ассеты: что есть и чего не хватает

В проекте появился комплект иллюстраций: `assets/caperucita/`, 38 отобранных изображений плюс 6 черновиков, манифест генерации с SHA-256 и галерея.

### Что сделано хорошо

**Стиль попал.** Акварель с карандашом, тёплая кремовая подложка, мягкие формы. Палитра совпадает с той, что я взял для визуального концепта: кремовый фон, красный капюшон как единственный яркий акцент, мох и кора в нейтралях.

**Речевые причуды персонажей читаются в статичной позе** — это прямое попадание в требование «ребёнок не читает». У Отто тяжёлые полуприкрытые веки, у Риты открытый рот и настороженная поза, Лоло стоит сгорбившись, сложив лапы, с тревожными бровями и без единого видимого зуба. Ребёнок понимает, кто перед ним, не зная ни слова.

**Инверсия волка удалась.** Лоло крупнее бабушки — контраст размера и есть источник комизма. Страшным он не выглядит ни на одном кадре.

**Лист улик уже реализует находки ревью.** Там есть перечёркнутая синяя капля для отрицательной улики `No se oye el agua` и кружащиеся сухие листья для «цветов нет» — ровно то «отсутствие показано чем-то, а не пустотой», которое появилось во втором раунде.

**Карты countable.** На целевой полянке варианта A три дерева намеренно разных пород и цветов — считать по одному легко, кусты визуально не спорят с деревьями за звание «дерева».

### Чего не хватает

| Пробел | Почему важно | Что делать |
|---|---|---|
| **Нет карточки «два дерева»** | Вариант C построен на `dos árboles`. На листе улик есть одиночные деревья и группа из трёх — двойки нет | Догенерировать одну карточку |
| **Слои не вырезаны** — это главное | Архитектура требует подсветки деревьев **по одному** при счёте, отдельных хит-зон для шести укрытий и состояний персонажа для Rive. Плоский PNG этого не даёт | Либо пересборка со слоями, либо хит-зоны + маски подсветки поверх плоского фона |
| **Вес** | 38 × ~3 МБ ≈ 110 МБ на один квест. Для пака, который скачивается на телефон, это неприемлемо | Пайплайн экспорта: WebP/AVIF, три плотности, цель 8–15 МБ на пак |
| **Пропорции 3:2** | 1536×1024. iPad — 4:3, телефон — около 19.5:9. И там и там будет либо кроп, либо поля | Задать безопасную зону: композиционно значимое держать в центральных 4:3, края считать расходуемыми |
| **Статика, не анимация** | README честно это говорит. Для Rive нужны разложенные элементы персонажа | На хакатон достаточно статики плюс простые твины; Rive — после |

### Пайплайн на хакатон

Плоские PNG + хит-зоны в `quest.json` закрывают демо без пересборки арта. Координаты трёх деревьев и шести укрытий прописываются в паке как нормализованные прямоугольники, подсветка рисуется поверх свечением. Это час работы вместо перегенерации, и `sensory-affordance` из раздела 6 при этом выполняется честно.

## 13. Что в MVP

**Входит:** один квест, три варианта загадки, четыре персонажа, полный конвейер диалога с интент-гейтом, авторский TTS, on-device детектор трёх слов, офлайн-прохождение, снапшот-возобновление, родительский отчёт, телеметрия по разделу 9.

**Не входит:** второй экран для родителя, коллекция «дом друзей» между квестами, свободные ответы ребёнка длиннее одного слова, другие языки изучения, подписка и биллинг.

**Порядок, в котором я бы строил:**

1. `@lq/runtime` + валидаторы контента. Пока их нет, любой контент — источник багов, которые ревью уже находило дважды.
2. Клиент на моках: без сети, с авторским аудио. Здесь проверяется ритм и посильность для трёхлетки — самое дорогое в исправлении и не требующее ни модели, ни ASR.
3. Интент-гейт и переходы состояний. Игра становится играбельной целиком.
4. Свободные реплики через Claude. Последними — потому что они улучшают игру, но не делают её работающей.

Этот порядок — прямое следствие того, что критичный путь не зависит от LLM. Обратный порядок (сначала интеграция с моделью) дал бы эффектное демо и неиграбельный продукт.

## 14. Риски

| Риск | Оценка | Что делаем |
|---|---|---|
| **Детское распознавание не работает** | Высокая вероятность, низкий ущерб | Архитектурно обезврежено: голос никогда не блокирует. Худший случай — ребёнок кладёт предметы касанием, квест проходится |
| **Задержка свободных реплик** | Средняя вероятность, средний ущерб | Fast mode, `effort: "low"`, кэш, маскировка характером, таймаут в авторский фолбэк |
| **Модель не держит контракт роли** | Средняя вероятность, **высокий ущерб** | Валидатор реплики + эвал-набор до релиза. Это главный кандидат на «начать на Opus 5 и не экономить» |
| **Стоимость сессии** | Низкая | ~$0.15–0.30; при платной модели окупается. Мерить с первого дня |
| **Комплаенс детских данных** | Средняя вероятность, **высокий ущерб** | Минимизация на уровне архитектуры, голос ребёнка не уходит с устройства. Юридическую часть закрыть до релиза |
| **Android-фрагментация офлайн-ASR** | Высокая | Бандлируемый WASM-детектор как база на всех платформах, нативные API — только ускорение |
| **Ландшафт-планшет не совпадает с реальностью** | Неизвестно | Проверить на первых же семьях, на каком устройстве они реально играют. Возможно, это телефон, и тогда компоновку надо пересматривать, а не адаптировать |
| **Context Router не пропускает параметры Anthropic** | Средняя вероятность, на хакатоне низкий ущерб | Проверить в первый день. Запасной путь: свободные реплики напрямую в Anthropic, Listen и Speak остаются на SLNG |
| **Внешний сервис отвалился на демо** | Низкая вероятность, **был бы высокий ущерб** | Обезврежено по построению: авторское аудио локально, квест доигрывается офлайн. Проверять регрессией в авиарежиме, а не надеждой на вайфай площадки |
| **Арт без вырезанных слоёв** | Точная | Хит-зоны в `quest.json` поверх плоских PNG — час работы вместо перегенерации. Пересборка со слоями после хакатона |
